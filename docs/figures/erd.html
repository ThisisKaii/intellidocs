Redis cache / behavior buffer / quota layer

Figure 36 (Supabase): Core account and authentication data are handled by the users and google_tokens tables, while the user's workspace — including hierarchical storage and actual text content — is managed via the folders, documents, and folder_documents structures. Document evolution is tracked in formatting_actions, working in tandem with ai_suggestions, grammar_issues, and suggestion_feedback.

Figure 37 (Redis): A volatile caching layer buffers active writing telemetry (REDIS_BEHAVIOR_BUFFER), accelerates prediction performance through short-lived lookups (REDIS_SUGGESTION_CACHE), and manages per-user request usage limits (REDIS_QUOTA_TRACKER).

Figure 38 (DuckDB): Buffered telemetry is periodically flushed into an analytical store. Raw user actions (DUCKDB_BEHAVIOR_EVENTS) are aggregated into structural behavioral footprints (DUCKDB_FORMATTING_FEATURES), serving as the foundational dataset for user-specific ML model fine-tuning.
