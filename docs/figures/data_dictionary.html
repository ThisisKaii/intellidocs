IntelliDocs Data Dictionary

Tables 4–22: structural definition of every database table used in IntelliDocs, including column names, data types, uniqueness constraints (U), descriptions, nullability, and key designations (PK/FK). Figure 36 stores in Supabase; Figure 37 in Redis; Figure 38 in DuckDB.

The database design provides a comprehensive structural foundation for managing an AI-assisted document editing platform through a network of interconnected tables. Core account and authentication data are handled by the users and google_tokens tables, while the workspace — hierarchical storage and text content — is managed via the folders, documents, and folder_documents structures. Document evolution is tracked in formatting_actions, working in tandem with the ai_suggestions, grammar_issues, and suggestion_feedback tables. A volatile Redis caching layer buffers writing telemetry, accelerates predictions, and manages per-user quotas. Periodically, buffered telemetry is flushed into an analytical DuckDB store, where raw actions are aggregated into structural behavioral footprints that serve as the foundational dataset for user-specific ML model fine-tuning.
