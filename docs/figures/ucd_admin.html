System Use Case Models — Administrator

Detailed specifications taken verbatim from the IntelliDocs manuscript (Figures 26–28).

Manage Users

Figure 26
Use Case Name
Manage Users
Purpose
It enables the administrator to maintain user accounts across the platform.
Triggering Actor
Administrator
Brief Description
The administrator can add a new user, edit an existing user's role, or deactivate a user's account. Adding a user always includes sending an invitation email, and deactivating a user is extended by a confirmation step.
Precondition
The administrator must be logged in and viewing the user management panel.
Post-condition
The user account is created, its role updated, or the account deactivated.
Steps
USERSYSTEM
1. The administrator enters a new user's details and adds them.1.1. Includes Send Invitation Email and creates the account.
2. The administrator changes a user's role.2.1. Updates the user's permissions accordingly.
3. The administrator selects a user to deactivate.3.1. Extends Deactivate User by prompting for confirmation before disabling the account.

Manage Reports

Figure 27
Use Case Name
Manage Reports
Purpose
It enables the administrator to generate and review system-wide usage reports.
Triggering Actor
Administrator
Brief Description
The administrator can generate a usage report, view an analytics dashboard, or export a report for offline use. Viewing the analytics dashboard always includes aggregating the tracked behavior data, and generating a usage report is extended by filtering the results to a specific date range.
Precondition
The administrator must be logged in and have access to the reports module.
Post-condition
A report or dashboard reflecting current system usage is produced or exported.
Steps
USERSYSTEM
1. The administrator opens the analytics dashboard.1.1. Includes Aggregate Behavior Data and renders the current usage metrics.
2. The administrator generates a usage report.2.1. Compiles the requested report from the aggregated data.
3. (Alternative) The administrator narrows the report to a date range.3.1. Extends Generate Usage Report by filtering the results to that range.

Moderate Documents

Figure 28
Use Case Name
Moderate Documents
Purpose
It enables the administrator to review and act on documents flagged as inappropriate or in violation of policy.
Triggering Actor
Administrator
Brief Description
The administrator reviews a flagged document, warns the responsible user, or removes the document entirely. Warning a user always includes sending them a notification, and removing a document is extended by a confirmation step.
Precondition
The administrator must be logged in and a document must have been flagged for review.
Post-condition
The flagged document is resolved by warning the user, removing the document, or both.
Steps
USERSYSTEM
1. The administrator opens a flagged document for review.1.1. Loads the document along with the details of the flag.
2. The administrator issues a warning to the user.2.1. Includes Notify User and sends the warning message.
3. The administrator chooses to remove the document.3.1. Extends Remove Document by prompting for confirmation before deletion.
