System Use Case Models — Student / General User

Detailed specifications taken verbatim from the IntelliDocs manuscript (Figures 18–24).

Authenticate Account

Figure 18
Use Case Name
Authenticate Account
Purpose
It enables users to securely gain access to the system or create a new account.
Triggering Actor
User
Brief Description
The user submits their credentials to log in, or resets a forgotten password. Submitting credentials always includes validating them against the stored account records, and is extended by the option to create a new account when the user has none, or to sign in with a linked Google account instead of a manual password.
Precondition
The user has a valid IntelliDocs account, a valid institutional email for account creation, or a linked Google account.
Post-condition
The user is authenticated and granted access to the system, or a new account is created.
Steps
USERSYSTEM
1. The user enters their email and password and submits their credentials.1.1. Includes Validate Credentials and checks them against the stored account records.
2. (Alternative) The user selects Google Account Login instead of entering a password.2.1. Extends Submit Credentials by authenticating the user through their linked Google account.
3. (Alternative) The user without an account selects Create New Account.3.1. Extends Submit Credentials by collecting the user's details and creating a new account.

Manage Documents

Figure 19
Use Case Name
Manage Documents
Purpose
It enables users to add, view, and remove documents within their personal workspace.
Triggering Actor
User
Brief Description
The user can upload a new document, view an existing one, or delete a document they no longer need. Uploading a document always includes an automatic formatting prediction pass, and deleting a document is extended by a confirmation step to prevent accidental loss.
Precondition
The user must be logged in and viewing their document workspace.
Post-condition
The document repository is updated to reflect the added, viewed, or removed document.
Steps
USERSYSTEM
1. The user selects a file and uploads it.1.1. Stores the document and includes a formatting prediction pass on the new file.
2. The user selects a document to delete.2.1. Extends Delete Document by prompting the user to confirm the action.
3. The user confirms the deletion.3.1. Permanently removes the document from the repository.

Manage Folders

Figure 20
Use Case Name
Manage Folders
Purpose
It enables users to create and organize folders to structure their documents.
Triggering Actor
User
Brief Description
The user can create a new folder, delete an existing one, or organize documents by moving them between folders. Deleting a folder is extended by a confirmation step, while organizing documents always includes the action of moving a document into a target folder.
Precondition
The user must be logged in and viewing their document workspace.
Post-condition
The folder structure is updated with the newly created, deleted, or reorganized folder.
Steps
USERSYSTEM
1. The user enters a folder name and creates it.1.1. Validates the name and adds the new folder to the workspace.
2. The user selects a folder to delete.2.1. Extends Delete Folder by prompting the user to confirm the action.
3. The user drags a document into a folder.3.1. Includes Move Document to Folder to relocate the file and updates the folder view.

Edit Document

Figure 21
Use Case Name
Edit Document
Purpose
It enables users to modify the content and formatting of a document, and to save their changes.
Triggering Actor
User
Brief Description
The user can format text, insert media such as images or tables, and save their changes. Formatting text always includes a formatting prediction pass, and the user may optionally accept an AI-generated suggestion, which extends the formatting process.
Precondition
The user must be logged in and have a document open in the editor.
Post-condition
The document is updated with the applied formatting, inserted media, and saved changes.
Steps
USERSYSTEM
1. The user selects text and applies formatting.1.1. Includes Predict Formatting to suggest a consistent style for the selection.
2. (Alternative) The user accepts the AI-generated suggestion instead of formatting manually.2.1. Extends Format Text by applying the suggested style automatically.
3. The user saves the document.3.1. Persists all changes to the document repository.

Predict Formatting

Figure 22
Use Case Name
Predict Formatting
Purpose
It enables the system to analyze a document and recommend formatting that keeps it consistent.
Triggering Actor
User
Brief Description
The system analyzes the structure of the active document and generates formatting suggestions, which the user may then apply. Analyzing the document structure always includes learning from the user's past edit history, and applying a suggestion is an optional extension of the formatting process.
Precondition
The user must be logged in and actively editing a document.
Post-condition
Formatting suggestions are generated and, if accepted, applied to the document.
Steps
USERSYSTEM
1. The user edits or formats a section of the document.1.1. Includes Learn From Edit History and analyzes the document's structure.
2. The system presents formatting suggestions.2.1. Generates a list of recommended formatting changes.
3. (Alternative) The user accepts a suggestion.3.1. Extends Apply Formatting by applying the accepted suggestion to the document.

Track Behavior

Figure 23
Use Case Name
Track Behavior
Purpose
It enables the system to monitor how users interact with IntelliDocs in order to improve their experience.
Triggering Actor
User
Brief Description
The system logs user actions as they use the platform and analyzes the collected data to identify usage patterns, which are compiled into a behavior report. Logging user actions always includes storing the activity data, and analyzing usage patterns may be extended by flagging anomalous usage.
Precondition
The user must be logged in and interacting with the system.
Post-condition
User activity is logged and, when requested, compiled into a behavior report.
Steps
USERSYSTEM
1. The user performs actions within the system (editing, uploading, formatting, etc.).1.1. Includes Store Activity Data and logs each action.
2. The system periodically analyzes the logged actions.2.1. Extends Analyze Usage Patterns by flagging unusual or anomalous usage.
3. The user or administrator requests a behavior summary.3.1. Generates a behavior report from the analyzed data.

Use AI Assistant

Figure 24
Use Case Name
Use AI Assistant
Purpose
It enables users to get AI-generated help while working on their documents.
Triggering Actor
User
Brief Description
The user can ask the assistant a question, review AI-generated suggestions, or request a summary of the document. Asking a question always includes retrieving the relevant context from the open document, reviewing suggestions is extended by the system generating them in the first place, and summarizing a document is extended by translating the summary into another language.
Precondition
The user must be logged in and have a document open.
Post-condition
The assistant's response is returned, a suggestion is accepted or rejected, or a summary is produced.
Steps
USERSYSTEM
1. The user types a question for the assistant.1.1. Includes Retrieve Document Context and formulates a response using it.
2. The user reviews a suggestion and accepts or rejects it.2.1. Extends Accept / Reject Suggestion by generating the suggestion for the user to review.
3. (Alternative) The user requests a summary in another language.3.1. Extends Summarize Document by translating the summary text.
